### 🔴 Issue #2: LỖI TOÁN HỌC Pooling Layer (BLOCKER - VALIDATED)

**Code trong ALLF v5.0 (Lines 268-291):**

```python
# SAI: Dimensional logic
avg_pool = tag_embeds.mean(dim=2, keepdim=True)  # [B, N, 1]
max_pool = tag_embeds.max(dim=2, keepdim=True)[0]  # [B, N, 1]

# SAI: Circular logic
avg_pool_expanded = avg_pool.expand(-1, -1, dim)  # [B, N, 512]
# => Lặp lại CÙNG MỘT giá trị scalar 512 lần! Vô nghĩa!

# Input dimension claim: 1025 (512+512+1)
# Nhưng logic không match
```

**❌ VẤN ĐỀ (Gemini critique ĐÚNG):**

1. **Lỗi 1:** `mean(dim=2)` tính mean theo embedding dimension → thu được scalar per tag
2. **Lỗi 2:** Expand scalar đó 512 lần → chỉ lặp lại cùng 1 giá trị, không có thông tin gì
3. **Lỗi 3:** Input dimension claim không consistent với implementation

**✅ CORRECT IMPLEMENTATION (2 options):**

**Option 1 - Simple & Effective (RECOMMENDED):**
```python
class SimpleWeightedPooling(nn.Module):
    """Attention-based pooling with frequency weighting"""
    def __init__(self, embed_dim=512):
        super().__init__()
        # Input: embedding + frequency per tag
        self.attention = nn.Sequential(
            nn.Linear(embed_dim + 1, 256),  # 513 → 256
            nn.ReLU(),
            nn.Linear(256, 1)  # → attention score
        )
    
    def forward(self, tag_embeds, tag_freqs):
        # tag_embeds: [B, N, 512]
        # tag_freqs: [B, N]
        
        # Concatenate frequency as feature
        features = torch.cat([
            tag_embeds,                    # [B, N, 512]
            tag_freqs.unsqueeze(-1)        # [B, N, 1]
        ], dim=-1)  # [B, N, 513]
        
        # Compute attention weights
        attn_scores = self.attention(features)  # [B, N, 1]
        attn_weights = F.softmax(attn_scores, dim=1)
        
        # Weighted sum
        output = (tag_embeds * attn_weights).sum(dim=1)  # [B, 512]
        return output
```

**Option 2 - With Set-level Statistics (nếu thật sự muốn statistics):**
```python
class StatisticsAwarePooling(nn.Module):
    """Pooling with set-level statistics (if really needed)"""
    def __init__(self, embed_dim=512):
        super().__init__()
        # Input: embedding + set_avg + frequency
        self.attention = nn.Sequential(
            nn.Linear(embed_dim * 2 + 1, 256),  # 1025 → 256
            nn.ReLU(),
            nn.Linear(256, 1)
        )
    
    def forward(self, tag_embeds, tag_freqs):
        # Compute set-level average CORRECTLY
        set_avg = tag_embeds.mean(dim=1, keepdim=True)  # [B, 1, 512]
        set_avg_expanded = set_avg.expand(-1, tag_embeds.size(1), -1)  # [B, N, 512]
        
        # Concatenate: [embedding, set_avg, frequency]
        features = torch.cat([
            tag_embeds,                    # [B, N, 512]
            set_avg_expanded,              # [B, N, 512]
            tag_freqs.unsqueeze(-1)        # [B, N, 1]
        ], dim=-1)  # [B, N, 1025]
        
        attn_scores = self.attention(features)
        attn_weights = F.softmax(attn_scores, dim=1)
        return (tag_embeds * attn_weights).sum(dim=1)
```

> [!WARNING]
> **Recommendation:** Dùng Option 1 (Simple). Research chưa chứng minh avg/max statistics có giá trị thực sự cho tag aggregation. Option 2 chỉ nên dùng nếu có ablation study chứng minh nó better.

### 🟡 Issue #4: FP16 Quantization Claims (WARNING - PARTIALLY VALIDATED)

**Claim trong ALLF v5.0:**

**❌ RESEARCH EVIDENCE - CLAIM QUÁ LẠC QUAN:**

Tôi đã research kỹ về FP16 quantization impact:

1. **✅ VALIDATED FACTS:**
   - FP16 cho **training activations:** minimal loss (~99% retained) ✅
   - FP16 cho **stored embeddings:** CÓ THỂ mất **2-5% semantic accuracy** ⚠️
   - **Underflow risk** với rare tags có small magnitude ⚠️
   
   > "FP16 quantization, while offering significant computational and memory advantages, can impact embedding quality and lead to degradation in semantic similarity" - Research summary
   
   > "The accuracy of similarity metrics, such as cosine similarity, typically decreases as the datatype precision is lowered" - arXiv research

2. **✅ SPECIFIC RISKS for ALLF:**
   - Sau domain adaptation, CLIP embeddings CÓ THỂ có:
     - Value ranges bị shift → FP16 underflow risk tăng
     - Inter-tag distances nhỏ hơn → precision loss impactful hơn
   - Rare tags (frequency < 100) đặc biệt vulnerable
   - Aggressive quantization (INT4, binary) còn tệ hơn nhiều

3. **✅ RESEARCH RECOMMENDATIONS:**
   - Mixed precision strategy: FP32 for critical tags, FP16 for common
   - Careful calibration needed for embedding-specific storage
   - Evaluation on BOTH average AND per-tag degradation

**✅ RECOMMENDED VALIDATION PLAN:**

```python
class AdaptiveDictionary:
    """Dictionary with dynamic caching for OOV tags"""
    def __init__(self, static_size=150_000):
        self.static_dict = load_top_k_tags(static_size)
        self.dynamic_cache = LRUCache(max_size=10_000)
        self.oov_tracker = Counter()  # Monitor OOV patterns
        
    def lookup_or_encode(self, tag):
        # 1. Static dictionary (fastest)
        if tag in self.static_dict:
            return self.static_dict[tag]
        
        # 2. Dynamic cache (fast)
        if tag in self.dynamic_cache:
            return self.dynamic_cache[tag]
        
        # 3. Fallback encode + cache
        embedding = self.fallback_encoder.encode(tag)
        self.dynamic_cache[tag] = embedding
        self.oov_tracker[tag] += 1
        
        return embedding
    
    def get_expansion_candidates(self, top_k=100):
        """Get popular OOV tags for dictionary expansion"""
        return self.oov_tracker.most_common(top_k)
```

### 🟡 Issue #6: Domain Adaptation - Catastrophic Forgetting Risk (WARNING - VALIDATED)

**Claim trong ALLF v5.0:**
Fine-tune CLIP ViT-B/32 on 100k Danbooru for 3 epochs

**❌ RESEARCH VALIDATION - RISK CAO (Gemini critique ĐÚNG):**

1. **✅ VALIDATED - Catastrophic Forgetting là REAL RISK:**
   - CLIP trained on 400M diverse image-text pairs
   - Fine-tuning on 100k anime-specific → **HIGH RISK** losing general semantics
   
   > "Fine-tuning CLIP with proper hyper-parameter refinement can significantly improve performance, but improper tuning can lead to catastrophic forgetting" - Research on CLIP fine-tuning
   
   > "Directly fine-tuning CLIP models with task-specific data can impair their original vision-language alignment and diminish their broader domain generalization capabilities" - arXiv research

2. **✅ VALIDATED - LoRA is SAFER but has LIMITATIONS:**
   - LoRA can still suffer catastrophic forgetting at higher ranks
   - LoRA: ~0.6M trainable params vs 63M full fine-tuning
   - Better control, but NOT immune to forgetting
   
   > "While LoRA is often believed to mitigate catastrophic forgetting by freezing most pre-trained weights, studies indicate that it can still suffer from this phenomenon, especially in sequential or continual learning scenarios" - Multiple research sources

3. **Missing Safeguards trong ALLF v5.0:**
   - ❌ No mention of freezing layers
   - ❌ No regularization strategy
   - ❌ No validation on general benchmarks (COCO, etc.)
   - ❌ No early stopping criteria

**✅ SAFER ALTERNATIVE (Research-backed):**

```python
from peft import LoraConfig, get_peft_model

# INSTEAD of full fine-tuning:

    r=16,  # rank (start conservative)

clip_model = CLIPTextModel.from_pretrained("openai/clip-vit-base-patch32")
```

```python
            'armor': ['armour'],
            'color': ['colour'],
        }
        
        # Plural handling
        self.plural_map = {
            'twin_tails': 'twin_tail',
            'cat_ears': 'cat_ear',
            'animal_ears': 'animal_ear',
        }
    
    def normalize(self, tag: str) -> List[str]:
        """Returns multiple normalized candidates"""
        candidates = []
        
        # Basic
        base = tag.lower().replace(' ', '_')
        candidates.append(base)
        
        # Aliases
        if base in self.aliases:
            candidates.append(self.aliases[base])
        
        # Synonyms
        for canonical, variants in self.synonyms.items():
            if base == canonical:
                candidates.extend(variants)
            elif base in variants:
                candidates.append(canonical)
        
        # Singular form
        if base in self.plural_map:
            candidates.append(self.plural_map[base])
        
        return list(set(candidates))
```
