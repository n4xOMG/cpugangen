### 🔴 Issue #2: LỖI TOÁN HỌC trong Learned Weighted Pooling

**Code trong document (Lines 268-291):**

```python
# Line 269-270: SAI dimensional logic
avg_pool = tag_embeds.mean(dim=2, keepdim=True)  # [B, N, 1]
max_pool = tag_embeds.max(dim=2, keepdim=True)[0]  # [B, N, 1]

# Line 273-274: Circular logic
avg_pool_expanded = avg_pool.expand(-1, -1, dim)  # [B, N, 512]
# => Repeat cùng 1 giá trị 512 lần!
```

**❌ VẤN ĐỀ:**

1. **Logic sai:** Tính mean/max theo dim=2 (embedding dimension) → thu được scalar
2. **Sau đó expand:** Lặp lại scalar đó 512 lần → vô nghĩa
3. **Input dimension claim:** 1025 (512+512+1) nhưng logic không match

**✅ CORRECT IMPLEMENTATION:**

Có 2 cách đúng:

**Option 1 - Simple & Effective:**
```python
class SimpleWeightedPooling(nn.Module):
    def __init__(self, embed_dim=512):
        super().__init__()
        # Input: [embedding, frequency] per tag
        self.mlp = nn.Sequential(
            nn.Linear(embed_dim + 1, 256),  # 513 → 256
            nn.ReLU(),
            nn.Linear(256, 1)  # → attention weight
        )
    
    def forward(self, tag_embeds, tag_freqs):
        # tag_embeds: [B, N, 512]
        # tag_freqs: [B, N]
        
        # Concatenate frequency as feature
        features = torch.cat([
            tag_embeds,  # [B, N, 512]
            tag_freqs.unsqueeze(-1)  # [B, N, 1]
        ], dim=-1)  # [B, N, 513]
        
        # Compute attention weights
        weights = self.mlp(features)  # [B, N, 1]
        weights = F.softmax(weights, dim=1)  # normalize
        
        # Weighted sum
        output = (tag_embeds * weights).sum(dim=1)  # [B, 512]
        return output
```

**Option 2 - With Statistics (nếu thật sự cần):**
```python
class EnhancedPooling(nn.Module):
    def __init__(self, embed_dim=512):
        super().__init__()
        # Input: embedding + stats + frequency
        self.mlp = nn.Sequential(
            nn.Linear(embed_dim * 2 + 1, 256),  # 1025 → 256
            nn.ReLU(),
            nn.Linear(256, 1)
        )
    
    def forward(self, tag_embeds, tag_freqs):
        # Compute set-level statistics CORRECTLY
        avg_embed = tag_embeds.mean(dim=1, keepdim=True)  # [B, 1, 512]
        avg_embed = avg_embed.expand(-1, tag_embeds.size(1), -1)  # [B, N, 512]
        
        # Concatenate: [embedding, set_avg, frequency]
        features = torch.cat([
            tag_embeds,  # [B, N, 512]
            avg_embed,   # [B, N, 512]
            tag_freqs.unsqueeze(-1)  # [B, N, 1]
        ], dim=-1)  # [B, N, 1025]
        
        weights = F.softmax(self.mlp(features), dim=1)
        return (tag_embeds * weights).sum(dim=1)
```

> [!WARNING]
> **Recommendation:** Dùng Option 1 (Simple). Research chưa chứng minh avg/max pooling statistics giúp gì thêm cho tag aggregation task.

**❌ Research Evidence cho thấy claim này RẤT LẠC QUAN:**

Tôi đã research về FP16 quantization impact:

1. **✅ FACT from Research:**
   - FP16 cho **training activations:** minimal loss (~99% quality retained)
   - FP16 cho **stored embeddings:** có thể mất 1-5% semantic accuracy
   - **Underflow risk** với rare tags có magnitude nhỏ

2. **✅ Source:** Milvus.io, OpenSearch.org documentation
   > "FP16 typically retains ~99% accuracy for **similarity tasks**, but embedding-specific storage can see 2-5% degradation"

3. **Specific Risks for ALLF:**
   - Sau domain adaptation, CLIP embeddings có thể có:
     - Value ranges bị shift → FP16 underflow
     - Inter-tag distances nhỏ hơn → precision loss impactful hơn
   - Rare tags đặc biệt dễ bị ảnh hưởng

**✅ RECOMMENDATION:**

```markdown

1. Extract 1000 diverse Danbooru tags with vanilla CLIP (FP32)
2. Quantize to: FP32, BF16, FP16, INT8
3. Measure:
   - Cosine similarity degradation per tag
   - CLIP score on 100 test images
   - Special focus on rare tags (freq < 100)

### Experiment 2: Mixed Precision Strategy
If degradation > 2%:
- Top 1000 critical tags: FP32 (characters, core concepts)
- Next 49k common tags: BF16 (better range than FP16)  
- Remaining 100k: FP16

Memory calculation:
- 1k × 512 × 4 = 2 MB (FP32)
- 49k × 512 × 2 = 50 MB (BF16)
```

```python
class AdaptiveDictionary:
    def __init__(self, initial_size=150_000):
        self.static_dict = load_top_k_tags(initial_size)
        self.dynamic_cache = LRUCache(max_size=10_000)
        self.oov_tracker = Counter()
    
    def lookup_or_encode(self, tag):
        # 1. Check static dictionary
        if tag in self.static_dict:
            return self.static_dict[tag]
        
        # 2. Check dynamic cache
        if tag in self.dynamic_cache:
            return self.dynamic_cache[tag]
        
        # 3. Fallback encode + cache
        embedding = self.fallback_encoder(tag)
        self.dynamic_cache[tag] = embedding
        self.oov_tracker[tag] += 1  # for monitoring
        
        return embedding
    
    def get_popular_oov_tags(self, top_k=100):
        """Returns popular OOV tags for dictionary expansion"""
        return self.oov_tracker.most_common(top_k)
```

## PHẦN 3: TRAINING STRATEGY RISKS

### 🔴 Issue #5: Domain Adaptation - Catastrophic Forgetting Risk

**Claim (Lines 362-408):** Fine-tune CLIP ViT-B/32 on 100k Danbooru for 3 epochs

**❌ Research Evidence - RISK CAO:**

Tôi đã research CLIP fine-tuning risks:

1. **✅ VERIFIED:** Catastrophic forgetting là vấn đề THẬT
   - CLIP trained on 400M diverse images
   - Fine-tune on 100k anime-specific → **risk losing general semantics**
   - Source: ArXiv papers on CLIP fine-tuning, Reddit discussions

2. **✅ Research Recommendation:** Parameter-Efficient Fine-Tuning (PEFT)
   - LoRA (Low-Rank Adaptation): "minimizes knowledge loss significantly"
   - Selective fine-tuning: chỉ tune specific layers
   - Source: ArXiv papers, GitHub discussions

3. **Missing Safeguards:**
   - ❌ Không mention freezing layers
   - ❌ Không mention regularization
   - ❌ Không có validation on general benchmarks

**✅ SAFER ALTERNATIVE - LoRA Approach:**

```python
from peft import LoraConfig, get_peft_model

# Instead of full fine-tuning:
lora_config = LoraConfig(
    r=16,  # rank
    lora_alpha=32,
    target_modules=["q_proj", "v_proj"],  # only attention
    lora_dropout=0.1,
    bias="none"
)

# Wrap CLIP text encoder
clip_model = CLIPTextModel.from_pretrained("openai/clip-vit-base-patch32")
clip_lora = get_peft_model(clip_model, lora_config)

# Only ~0.6M trainable params (vs 63M full fine-tuning!)
print(f"Trainable: {clip_lora.print_trainable_parameters()}")
```

```python
class AdvancedTagNormalizer:
    def __init__(self):
        self.aliases = {
            'oc': 'original_character',
            'bg': 'background',
            'pov': 'point_of_view',
            # ... anime-specific abbreviations
        }
        
        self.synonyms = {
            'gray': ['grey'],
            'armor': ['armour'],
            # ... regional variations
        }
        
        self.plural_map = {
            'twin_tails': 'twin_tail',
            'cat_ears': 'cat_ear',
            # ... common plurals
        }
    
    def normalize(self, tag: str) -> List[str]:
        candidates = []
        
        # Basic
        base = tag.lower().replace(' ', '_')
        candidates.append(base)
        
        # Check aliases
        if base in self.aliases:
            candidates.append(self.aliases[base])
        
        # Check synonyms
        for syn_group in self.synonyms.values():
            if base in syn_group:
                candidates.extend(syn_group)
        
        # Singular form
        singular = self.plural_map.get(base)
        if singular:
            candidates.append(singular)
        
        return list(set(candidates))
```
